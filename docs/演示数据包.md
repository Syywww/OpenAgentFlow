# P33 一键演示数据与交付样例包

P33 演示数据包用于让本地环境快速具备一套完整可体验的数据链路：模型配置、Prompt、Agent、知识库、工具、工作流、评测集、多 Agent 团队和 Memory。

## 包含内容

| 类型 | 样例 |
| --- | --- |
| Prompt | 演示客服助手 System Prompt、演示可信 RAG 回答 Prompt |
| Agent | 客服助手、订单分析助手、质量复核助手 |
| 知识库 | 产品手册知识库，内置客服政策、订单查询、可信回答和工单升级分片 |
| 工具 | REST 订单状态查询、Webhook 客户事件推送、只读订单 SQL 查询 |
| 工作流 | 演示客服 RAG 工具工作流，包含开始、RAG、工具、LLM、输出、结束节点 |
| 多 Agent | 演示客服协作团队，包含主控、执行、复核三个角色 |
| 评测 | 演示客服问答评测集，覆盖工具调用、风险边界和可信回答 |
| Memory | 客服长期记忆模板和演示偏好记忆 |

## 初始化

默认连接本地 MySQL：

```powershell
cd E:\xm\OpenAgentFlow-Java\dm
.\scripts\init-demo-data.ps1
```

脚本会先检查 `workflow_run.locked_by` 字段是否存在；如果旧库还没有执行工作流可靠性迁移，会自动应用 `V028__workflow_execution_reliability_final.sql`，再导入 P33 演示数据。

指定 MySQL 客户端路径：

```powershell
.\scripts\init-demo-data.ps1 -MysqlExe "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"
```

如果希望脚本同时写入本地模型 Key，可以传入：

```powershell
.\scripts\init-demo-data.ps1 -DemoApiKey "你的本地模型APIKey"
```

脚本不会把 Key 写入仓库文件，也不会在控制台输出明文。

## 推荐体验路径

1. 登录 `admin / 123456`。
2. 进入系统设置，确认豆包模型供应商和模型配置可见。
3. 进入智能体，查看“客服助手”以及绑定的知识库、工具和工作流。
4. 进入知识库，打开“产品手册知识库”，执行检索测试。
5. 进入调试台，选择“客服助手”，输入：`订单 OAF-DEMO-1001 到哪里了？如果客户要求退款应该怎么处理？`
6. 进入工具中心，查看三类工具的 Schema、风险等级和测试用例。
7. 进入工作流，打开“演示客服 RAG 工具工作流”，查看节点和连线。
8. 进入多 Agent 协作，查看“演示客服协作团队”。
9. 进入评测中心，查看“演示客服问答评测集”。
10. 进入交付验收中心，查看“演示数据”检查项是否通过。

## 数据安全说明

- SQL 文件不包含真实 API Key。
- 工具 URL 使用 `mock.openagentflow.local`，用于配置展示和治理演示。
- 知识库向量使用 MySQL 兜底数据，真实环境可以重新上传文档或重建向量写入 Milvus。
