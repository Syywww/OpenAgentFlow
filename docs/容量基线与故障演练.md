# 容量基线与故障演练

## 目标基线

正式上线前必须在与生产同规格的预发布环境建立容量基线，至少覆盖以下场景：

| 场景 | 基线目标 | 核心指标 |
| --- | --- | --- |
| 文档上传 | 1 GB 单文件、1 万文件批次 | 接收成功率、对象存储吞吐、DAG积压 |
| 文档切片 | 1000 万有效分片 | 阶段P95、堆内存、失败分片数 |
| Embedding | 持续运行2小时 | 模型429、QPS、并发许可等待时间 |
| 向量写入 | 1000万向量 | Milvus写入P95、索引构建时间 |
| Agent会话 | 200并发逐步扩容 | 首Token、总耗时、SSE断开率 |
| 任务中心 | 100并发查询 | API P95、MySQL慢查询 |

## 执行方式

安装 k6 后执行：

```powershell
$env:OAF_BASE_URL='http://localhost:8080/api'
$env:OAF_TOKEN='登录后JWT'
$env:OAF_AGENT_ID='待压测智能体ID'
k6 run scripts/load-test/k6-runtime.js
k6 run scripts/load-test/k6-task-center.js
```

## 故障演练矩阵

| 故障 | 操作 | 正确表现 |
| --- | --- | --- |
| Kafka短时不可用 | `scripts/fault-injection/kafka-pause.ps1` | Outbox累积，Broker恢复后继续投递 |
| Worker执行中退出 | `scripts/fault-injection/worker-kill.ps1` | 心跳过期后新Worker接管，旧代次不能提交 |
| Embedding返回429 | 在测试网关注入429 | Redis背压生效，任务进入延迟重试 |
| Milvus不可用 | 暂停Milvus | 严格模式不标成功，任务重试后进入死信 |
| MinIO超时 | 注入网络延迟 | 上传或阶段任务明确失败且可重试 |
| 重复Kafka消息 | 重复投递相同taskId | 只有一个Worker获得执行租约 |

每轮演练应保存指标截图、错误摘要和容量结论到外部交付工单，不写入项目 README。
