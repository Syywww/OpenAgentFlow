# 高可用与容灾

## 生产拓扑

- API、Agent Runtime、文档 Worker、集成 Worker 独立部署，至少两个副本。
- Kafka 至少三个 Broker，生产 Topic 副本数为三，最小同步副本数为二。
- MySQL 使用主从或云高可用实例，Redis 使用 Sentinel 或 Cluster。
- MinIO 使用分布式模式或替换为兼容 S3 的云对象存储。
- Milvus 使用集群模式，etcd、对象存储和 Query/Data 节点分别配置高可用。

## 目标

| 等级 | RPO | RTO | 适用范围 |
| --- | --- | --- | --- |
| 核心元数据 | 不超过5分钟 | 不超过30分钟 | 用户、Agent、知识库、工作流、权限 |
| 对象文件 | 不超过15分钟 | 不超过2小时 | 原文档和流水线阶段产物 |
| 可重建索引 | 不强制同步备份 | 不超过4小时 | Milvus、OpenSearch索引 |

## 备份与恢复

MySQL备份：

```powershell
$env:MYSQL_PWD='数据库密码'
.\scripts\backup\mysql-backup.ps1 -OutputDirectory E:\backup\openagentflow
```

MySQL恢复：

```powershell
$env:MYSQL_PWD='数据库密码'
.\scripts\backup\mysql-restore.ps1 -BackupFile E:\backup\openagentflow\openagentflow-时间.sql
```

对象存储必须开启版本控制、生命周期和跨区域复制。Milvus与关键词索引应从MySQL分片元数据和对象存储阶段产物重建，激活前通过集合别名进行蓝绿切换。

## 发布与故障切换

Helm Chart 位于 `deploy/helm/openagentflow`。发布使用零不可用滚动策略，Pod退出前预留十五秒并停止领取新消息；PDB与反亲和避免节点维护同时清空全部API副本。KEDA依据文档Topic积压扩容Worker，最大有效消费实例数不能超过Topic分区数。
