# 权限治理增强设计

## 目标

在现有 JWT、Redis、系统 RBAC、工作空间成员和资源 ACL 基础上，建立默认拒绝、空间隔离、最小权限和可审计的统一权限治理体系，避免新增接口依赖开发人员手工补充权限判断。

## 总体架构

权限判断分为四层：Spring Security 统一路由权限、工作空间成员与空间角色权限、资源级 ACL、Service 业务约束。前端菜单和按钮权限只改善交互，后端始终执行最终裁决。

请求先经过 JWT 与 Redis 令牌状态检查，再由工作空间过滤器绑定可信 `WorkspaceContextHolder`。统一路由授权管理器同时读取系统权限和当前工作空间角色权限，并根据数据库 `iam_permission.api_method/api_path` 与内置路由策略决定是否放行。资源详情和写操作继续由统一 ACL 服务执行所有者、用户、角色、部门授权判断。

## 权限边界

- `ROLE_super_admin` 与 `ROLE_admin` 是平台级角色，可以跨空间执行平台管理。
- `workspace:manage`、`agent:manage` 等普通权限不再自动获得跨空间能力。
- 工作空间 `owner`、`admin`、`developer`、`auditor`、`viewer` 通过空间角色权限表获得当前空间内权限。
- 未携带工作空间上下文的租户资源请求默认拒绝；认证、IAM 平台管理、健康检查等明确路径进入平台白名单。
- 数据库权限路径命中时必须拥有对应权限；严格模式下未声明的业务路由拒绝访问，开发环境可使用审计模式逐步补齐。

## 数据模型

- `iam_workspace_role`：工作空间角色定义和数据范围。
- `iam_workspace_role_permission`：空间角色与系统权限点关系。
- `iam_workspace_member_role`：用户在空间内可拥有多个角色。
- `iam_role_department`：自定义部门数据范围。
- 扩展 `iam_resource_acl`：增加工作空间、状态、到期时间和授权来源。
- `iam_authorization_audit`：保存授权、撤销、角色分配、会话撤销等权限变更明细。

## 会话安全

Redis 在保存令牌状态时同步维护用户令牌集合。管理员禁用用户、删除用户或调整系统角色后立即撤销该用户全部令牌；IAM 页面提供强制下线入口。每次请求仍重新加载数据库角色与权限，因此启用状态和权限变化不会长期滞留。

## 前端

增加统一 `canAccess` 与 `v-permission` 指令，敏感按钮根据权限隐藏。系统设置增加权限治理卡片，展示空间角色、数据范围、资源授权和会话操作；所有请求仍以服务端响应为准。

## 异常与审计

- 未登录返回 `401`。
- 缺少路由权限、空间成员身份或资源权限返回 `403`，使用可区分的错误编码。
- 权限变更写入授权审计表，普通接口访问继续由现有操作审计过滤器处理。
- 不在日志和响应中输出密码、JWT、API Key 或 Webhook 密钥。

## 测试策略

- 单元测试覆盖平台角色边界、路由权限解析、空间路径分类、数据范围和 ACL 到期规则。
- Spring Security 集成测试覆盖匿名、普通用户、空间角色和平台管理员。
- Flyway 测试覆盖新增表、索引、中文注释和两份 SQL 一致性。
- 前端单元测试覆盖按钮权限和菜单权限，生产构建检查类型与模板。
