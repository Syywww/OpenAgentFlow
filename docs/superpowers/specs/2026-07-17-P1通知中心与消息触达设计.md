# P1 通知中心与消息触达设计

## 目标

把现有仅由运营告警写入数据库、前端以静态内容展示的通知能力，补全为面向每个登录用户的真实通知中心，并将通知渠道从只读配置升级为可管理、可测试、可补偿的外部触达能力。

## 范围

### 个人通知中心

- 按未读、已读、归档、通知类型、严重级别和关键字分页查询。
- 提供未读总数与各级别汇总。
- 支持单条已读、批量已读、全部已读、单条归档和批量归档。
- 支持通知偏好、最低接收级别、免打扰时段和摘要频率。
- 通知可携带业务资源、跳转地址、去重键和失效时间。

### 统一通知发布

- 提供内部发布服务和受权限保护的管理接口。
- 支持按用户、角色或全体启用用户分发。
- 使用去重键避免同一业务事件重复写入。
- 发布时根据用户偏好过滤通知类型和最低严重级别。

### 外部消息触达

- 运营通知渠道支持新增、编辑、启停、删除和连通性测试。
- Webhook、钉钉和企业微信统一走 JSON Webhook 协议。
- 可选 HMAC-SHA256 签名，支持请求超时和自定义请求头。
- 投递失败继续复用指数退避、最大次数和死信收敛机制。
- 提供投递明细分页和人工重投接口。

### 前端

- 顶部铃铛展示真实未读数，抽屉加载最近通知并可直接标记已读。
- 通知中心页面按卡片切换全部、未读、已读、归档与偏好设置。
- 运营监控通知渠道页提供真实管理弹框、测试和投递明细。

## 安全边界

- 用户只能查看和修改自己的接收状态与偏好。
- 渠道配置和统一发布仅允许具备管理权限的用户操作。
- 渠道密钥不在列表接口回显，日志不输出密钥和完整请求头。
- 外部地址只允许 HTTP/HTTPS，签名在发送时临时计算。

## 完成标准

- 后端测试覆盖用户隔离、状态变更、偏好过滤、去重和渠道签名。
- 前端生产构建通过，抽屉和完整页面均不再使用静态通知数组。
