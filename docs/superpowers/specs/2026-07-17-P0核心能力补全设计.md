# P0 核心能力补全设计

## 目标

将模板广场、工作流高级执行和 MCP 接入中已经展示但尚未闭环的能力补全为可运行、可追踪、可测试的真实实现，同时继续保持 OpenAgentFlow-Java 的原生 Runtime 架构。

## 解决方案模板

- 四个内置解决方案必须包含 Prompt、工具、知识库、文档、切片、工作流、Agent、团队和长期记忆资源。
- 三个历史内置模板必须拥有已发布版本和可安装资源，不能继续以无版本状态展示安装按钮。
- 安装仍复用 `agent_template_resource` 的拓扑复制和 ID 重映射，不增加第二套安装器。
- 内置资源使用数据库快照交付；向量由安装后的文档流水线按目标空间模型重建，避免复制无效 Milvus 主键。

## 工作流执行

- `PARALLEL` 根据出边创建分支，使用有界执行器并发执行，每个分支使用独立上下文副本。
- `JOIN` 只在目标分支全部完成后运行，按节点键稳定排序合并结果，冲突值写入分支命名空间。
- 分支步骤继续写入 `workflow_step_run` 和 Runtime Trace；任一分支失败时遵循节点失败策略。
- 插件节点通过 `WorkflowNodePlugin` SPI 执行，注册中心同时加载 Spring Bean 与 Java `ServiceLoader` 实现；未知插件明确失败，不再返回成功占位结果。

## 队列、灰度与评测

- 新增 `WORKFLOW_RUN` Kafka 异步任务及处理器，复用现有 Outbox、幂等键、租约、重试和死信链路。
- 灰度运行以工作流 ID、调用用户和幂等键计算稳定哈希，在当前版本与上一已发布版本之间选择；同一请求始终命中同一版本。
- 评测任务设置 `workflowId` 时直接执行工作流，并将输出、Token、耗时和 Trace Run ID 回写样本结果。

## MCP 传输

- 保留 `McpClientService` 作为平台适配入口，内部拆分 `http`、`streamable_http`、`sse`、`stdio` 传输。
- Streamable HTTP 支持 JSON 与 SSE 响应、`Mcp-Session-Id`、初始化完成通知和会话失效重建。
- legacy SSE 支持 endpoint 事件、消息 POST、请求响应关联和超时关闭。
- stdio 使用 `ProcessBuilder` 启动子进程，逐行收发 JSON-RPC，独立读取 stderr，并在超时、停用或应用关闭时回收进程。
- stdio 默认只允许配置白名单中的命令，环境变量按 Server 配置注入，命令和密钥不写入业务日志。

## 测试与兼容

- 为灰度路由、并行合并、插件注册、MCP SSE 解析、stdio 命令策略和模板资源清单分别增加单元测试。
- Flyway 新迁移只补数据和新增必要字段，不重写历史迁移。
- 保持现有 HTTP MCP 配置兼容；旧 `http` 类型按 Streamable HTTP 优先、普通 JSON-RPC 兼容方式运行。
