# P76 可重复构建与质量门禁设计

## 目标

让后端测试在干净 CI 环境中自行准备所需数据库，不再依赖开发者本机已经启动的 MySQL、Redis、Kafka、Milvus 或 MinIO；同时把前端浏览器测试从“只看见登录页”提升到覆盖登录成功、默认工作空间选择和权限菜单收敛。

## 范围

1. 新增统一测试配置，关闭 Kafka 消费、Outbox 发布、Milvus、MinIO、OpenSearch、OTLP 和后台巡检任务。
2. 新增共享 MySQL Testcontainers 基类，通过 `DynamicPropertySource` 注入数据源并执行完整 Flyway 迁移。
3. 模板市场、模板安装、权限治理等依赖种子数据的测试迁移到共享容器，不再读取本机数据库。
4. 应用上下文测试使用测试配置，确保没有 Milvus 时也能检查 Spring 容器装配。
5. CI 在后端任务开始时检查 Docker，避免基础设施测试被静默跳过。
6. Playwright 使用接口级可控响应完成登录成功、默认空间头选择和无权限菜单隐藏场景。

## 架构

测试分为三层：纯单元测试不启动 Spring；容器集成测试继承 `MySqlContainerIntegrationTestSupport`；浏览器测试由 Playwright 启动独立 Vite 服务并拦截确定性接口响应。测试 Profile 只负责关闭外部副作用，真实 MySQL 结构和种子数据始终由 Flyway 在容器中生成。

## 错误处理

- CI 没有可用 Docker 时立即失败，不允许以跳过基础设施测试的方式通过门禁。
- 本地没有 Docker 时，容器集成测试允许跳过，纯单元测试、类型检查和构建仍可执行。
- 测试禁止调用真实模型、Embedding、Milvus、外部 Webhook 和通知渠道。

## 成功标准

- 本机外部适配器关闭时，应用上下文测试可以通过。
- Docker 可用的干净环境能执行 V001-V055、模板安装和权限治理测试。
- 前端浏览器测试能够从登录页进入工作台、选择默认空间并隐藏无权限菜单。
- README 与 CI 使用方式同步更新。
