# 运营监控与告警中心

P17 运营监控与告警中心用于把平台运行状态、关键业务指标、健康巡检和告警处置统一收口，面向可运营、可治理、可交付场景提供基础可观测能力。

## 能力范围

- 运营总览：统计运行次数、成功率、平均耗时、Token、成本、未处理告警、健康异常项、任务积压、风险事件和知识治理问题。
- 健康矩阵：按 MySQL、Redis、Milvus、模型供应商、异步任务队列、API 质量、模型调用质量展示健康状态、最后检测时间和异常原因。
- 手动巡检：支持一键触发巡检，重新评估健康检查项和告警规则。
- 告警规则：支持指标、比较符、阈值、等级、冷却时间、通知渠道、启停状态的创建、编辑、删除和分页查询。
- 告警事件：支持按状态、等级、规则筛选告警事件，记录触发值、阈值、详情、触发时间、恢复时间、处理人和处理备注。
- 通知渠道：支持站内通知和 Webhook 通知渠道配置，默认告警会写入站内通知并分发给管理员。
- Trace 关联：运营告警围绕运行记录、模型调用、任务、风险、知识治理等统一指标生成，便于后续和 Trace、审计、成本中心联动。

## 后端接口

后端接口统一位于 `/api/ops-monitor`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/overview` | 查询运营监控总览 |
| GET | `/health` | 查询健康矩阵 |
| POST | `/inspect` | 立即执行一次健康巡检和告警规则评估 |
| GET | `/rules` | 分页查询告警规则 |
| POST | `/rules` | 创建告警规则 |
| PUT | `/rules/{id}` | 更新告警规则 |
| DELETE | `/rules/{id}` | 删除告警规则 |
| GET | `/events` | 分页查询告警事件 |
| POST | `/events/{id}/handle` | 处理告警事件 |
| GET | `/checks` | 查询巡检项列表 |
| GET | `/channels` | 查询通知渠道列表 |

默认权限：

- `ops:monitor:view`：查看运营监控、健康矩阵、告警事件、巡检项和通知渠道。
- `ops:monitor:manage`：触发巡检、维护告警规则、处理告警事件。

## 数据表

SQL 迁移文件为 `openagentflow-sql/mysql/V016__ops_monitor_alert_center.sql`，包含以下表：

| 表名 | 说明 |
| --- | --- |
| `ops_alert_rule` | 运营告警规则表 |
| `ops_alert_event` | 运营告警事件表 |
| `ops_health_check` | 平台健康巡检项表 |
| `ops_notify_channel` | 运营通知渠道表 |

所有表和字段均包含中文注释，并初始化站内通知渠道、Webhook 占位渠道、7 个巡检项、5 条默认告警规则和管理员权限。

## 前端入口

左侧导航新增“运营监控”，路由为 `/ops`。

页面包含：

- 总览卡片
- 健康矩阵
- 告警事件列表和处置表单
- 告警规则列表和创建/编辑表单
- 健康巡检项列表
- 通知渠道列表

所有列表统一按每页 10 条展示，遵守项目全局分页约定。
