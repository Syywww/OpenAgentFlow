# P43-P52生产闭环

## 文档物理DAG

新上传文档依次产生独立Kafka任务：

```text
DOCUMENT_PIPELINE_PARSE
  -> DOCUMENT_PIPELINE_CHUNK
  -> DOCUMENT_PIPELINE_EMBED x N
  -> DOCUMENT_PIPELINE_VECTOR_WRITE x N
  -> DOCUMENT_PIPELINE_FINALIZE
```

解析文本、稳定分片清单和向量分片均保存到MinIO。每个分片具有独立任务ID、幂等键、Fencing Token、对象产物与错误状态，最后一个成功分片负责幂等创建下一阶段。

## Runtime角色

| Profile | 用途 | Kafka消费 | 聊天流量 |
| --- | --- | --- | --- |
| `prod,api` | 管理API与任务投递 | 关闭 | 关闭 |
| `prod,runtime` | Agent对话、SSE、模型调用 | 关闭 | 开启 |
| `prod,worker` | 文档、评测、MCP等异步任务 | 开启 | 关闭 |

Runtime停止令牌保存到Redis，各Runtime实例每500毫秒检查本实例活动运行并主动关闭模型HTTP Future或响应流。

## 检索发布

OpenSearch负责BM25关键词召回，Milvus负责向量召回。索引新版本构建完成后先调用就绪接口，再通过激活接口原子切换Milvus Alias。删除文档会同步执行MinIO对象删除、Milvus过滤删除、OpenSearch Delete By Query和MySQL映射删除。

## 发布门禁

Agent发布默认要求最近一次评测任务成功，并满足最低平均得分、最大失败率、最大耗时、安全与成本条件。门禁失败会阻断发布，门禁数据使用独立事务保存。

## 供应链

`.github/workflows/supply-chain.yml`执行Maven测试、CycloneDX SBOM、Trivy镜像与源码扫描、许可证检查和Cosign无密钥签名。生产制品只有在严重与高危漏洞为零、许可证和密钥扫描通过且包含SBOM与签名时才能登记为准入状态。
