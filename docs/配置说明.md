# 配置说明

后端通过环境变量读取配置，未设置时使用本地开发默认值。生产环境请使用 `.env.prod.example` 生成 `.env.prod`，并启用 `SPRING_PROFILES_ACTIVE=prod`。

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `OAF_MYSQL_URL` | MySQL JDBC 地址 | 本地 `openagentflow` 数据库 |
| `OAF_MYSQL_USERNAME` | MySQL 用户名 | `root` |
| `OAF_MYSQL_PASSWORD` | MySQL 密码 | `123456` |
| `OAF_MYSQL_ROOT_PASSWORD` | MySQL root 密码，Docker 初始化使用 | `123456` |
| `OAF_REDIS_HOST` | Redis 地址 | `localhost` |
| `OAF_REDIS_PORT` | Redis 端口 | `6379` |
| `OAF_REDIS_DATABASE` | Redis database | `0` |
| `OAF_REDIS_PASSWORD` | Redis 密码 | 空 |
| `OAF_MILVUS_HOST` | Milvus 地址 | `localhost` |
| `OAF_MILVUS_PORT` | Milvus 端口 | `19530` |
| `OAF_JWT_SECRET` | JWT 签名密钥 | 本地开发占位密钥 |
| `OAF_JWT_EXPIRE_MINUTES` | JWT 有效期分钟数 | `1440` |
| `OAF_CORS_ALLOWED_ORIGINS` | CORS 允许来源，多个域名用英文逗号分隔 | 本地前端地址 |
| `OAF_SWAGGER_ENABLED` | 生产 Profile 是否开启 Swagger | `false` |
| `OAF_BACKEND_MEM_LIMIT` | 生产后端容器内存限制 | `2g` |
| `OAF_BACKEND_CPUS` | 生产后端容器 CPU 限制 | `2` |
| `OAF_FRONTEND_MEM_LIMIT` | 生产前端容器内存限制 | `256m` |
| `OAF_FRONTEND_CPUS` | 生产前端容器 CPU 限制 | `0.5` |
| `OAF_JAVA_OPTS` | 后端 JVM 启动参数 | MaxRAMPercentage 75 |
| `VITE_API_BASE_URL` | 前端接口基础地址 | `http://localhost:8080/api` |

## 模型 API Key

不要把真实模型 API Key 提交到 GitHub。

SQL 种子脚本只初始化模型供应商和模型接入点，不保存真实 API Key。真实 Key 请在系统设置页配置，或仅保存到本地数据库中。

## MySQL 初始化

Docker Compose 的 MySQL 服务会挂载：

```text
openagentflow-sql/mysql -> /docker-entrypoint-initdb.d
```

首次创建数据库时，MySQL 会自动执行 `V001` 到当前最新版本初始化脚本。

## 生产环境建议

- 使用强随机值覆盖 `OAF_JWT_SECRET`，长度不少于 32 位。
- 使用独立数据库账号替代 `root`。
- 使用 `.env.prod` 和 `docker-compose.prod.yml` 部署生产环境。
- 将 `OAF_CORS_ALLOWED_ORIGINS` 收敛到正式域名，不使用 localhost 或通配来源。
- 生产 Profile 默认关闭 Swagger，如需排查临时开启 `OAF_SWAGGER_ENABLED=true`，使用后关闭。
- 为 MySQL、Redis、Milvus 配置持久化备份。
- 不要把 `.env` 提交到仓库。
## 模型网关配置

- 模型网关不需要新增环境变量，默认读取 MySQL 中的 `model_route_policy`、`model_route_candidate`、`model_config` 和 `model_provider`。
- 未显式指定模型且 Agent 未绑定模型时，Agent 对话会按 `AGENT_CHAT` 场景策略选择候选模型。
- 工作流 LLM 节点未配置模型时同样会进入模型网关；显式配置模型时保持直连。
- 失败回退由 `model_route_policy.fallback_enabled` 控制，候选顺序由 `model_route_candidate.priority` 和 `weight` 控制。
- 每次真实 LLM 调用会在 `runtime_llm_call.route_decision` 中记录决策快照，便于后续 Trace、用量和审计排查。
